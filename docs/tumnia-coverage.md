# Покритие на изискванията „Тъмния" — състояние и интеграция

Преглед на `Тъмния_1.docx` и `Тъмния_2.docx` спрямо системата, по източници на истина
(схема `server/db.js`, маршрути, UI страници, тестове). Дата: 2026-11-24.

Легенда: **ГОТОВО** — работи и е покрито с тест; **ЧАСТИЧНО** — механизмът съществува,
но липсва част от желаното поведение; **ЛИПСВА** — няма реализация.

## Тъмния_1 — Договори, Приложения, Картон на обекта, КС, Табло

### Договори и приложения

| Изискване | Състояние | Къде е интегрирано |
|---|---|---|
| Картон на обекта в Клиенти (таб при клиента) | **ЛИПСВА** | `Customers.tsx` не показва обектите на клиента. Заявката по връзка `customers↔projects` съществува — остава UI таб „Обекти на клиента". |
| Импорт на файл в Приложения | **ГОТОВО** | `documents` с `entity_type='contract'`, категории `contract/appendix/act` — нова верига за прикачване в ContractTab (тази сесия). |
| Вид на договора — падащо меню (наш образец / на възложителя) | **ГОТОВО** | `contracts.contract_kind` (`standard` / `client_template`). |
| Начин на плащане 50/30/20 в евро | **ГОТОВО** | При подписване се засяват `contract_payments` аванс 50 % / междинно 30 % / окончателно 20 % (тест „signing seeds the 50/30/20 schedule"). |
| Срок за производство и доставка | **ГОТОВО** | `contracts.prod_delivery_days`; реалната дата се извежда от платения аванс (`delivery_due`, фикс тази сесия — точка #8). |

| Специални условия | **ГОТОВО** | `contracts.special_terms`. |

| Финално подписани SCAN (договор/приложения/актове/ППП) | **ГОТОВО** | `documents` + `document_versions` с версии (тази сесия, точка #4) — `POST /api/documents/:did/versions`, всички версии се пазят, линкове per версия. |

### Жизнен цикъл и уведомяване

| Изискване | Състояние | Къде е интегрирано |
|---|---|---|
| ГОТОВО → проблем → промяна → достига до другите роли | **ГОТОВО** | Reopen/correction flows + заявки за промяна + `emit()` → уведомления по отдели; тази сесия е поправен revert-проблемът при изтриване (точка #11 — tombstone вместо FK-грянх). |
| Банкови извлечения за подотчетни карти (приход/разход по карта) | **ЧАСТИЧНО** | `accountable_persons` + движения „дадено-изразходено-върнато=остатък" (тест). Импорт на банково извлечение като файл — ръчно въвеждане. |
| СЕБЕСТОЙНОСТ автоматично от Оферти във Финанси | **ГОТОВО** | `unit_cost` по редове → `cost_price` в `progressSummary`; от тази сесия видимо и в списъка Обекти за финансовите роли (точка #9). |

## Тъмния_2 — Финанси по договора + регистър на доставните поръчки

### Срокове и плащания по договора

| Изискване | Състояние | Къде е интегрирано |
|---|---|---|
| Срок за готовност, дата на постъпване на сумата | **ГОТОВО** | `contract_payments` (amount, paid_at) + времева линия. |
| Авансова / междинна / окончателна стойност с ДДС | **ГОТОВО** | Трите млечни камъка се засяват при подписване; стойности в EUR (валутата е базова). |
| Срок за производство/транспорт/монтаж в дни | **ГОТОВО** | `prod_delivery_days`, `install_days`; транспортните дни текат по доставните поръчки (`transport_days`). |

### Регистър „Доставчици / поръчки" — Тъмния_2 спецификацията е реализирана почти 1:1

| Колона от шаблона на Тъмния_2 | Поле в `supplier_orders` | Състояние |
|---|---|---|
| № Поз. (Прил. 1) | `project_line_id` (връзка към позиция от приложението) | **ГОТОВО** |
| Доставчик / Производител | `supplier_id` | **ГОТОВО** |
| № на документ за поръчка | `order_doc_no` | **ГОТОВО** |
| Обща стойност (EUR) | `total_eur` | **ГОТОВО** |
| Аванс — сума | `advance_eur` | **ГОТОВО** |
| Дата на плащане на аванс | `advance_paid_at` | **ГОТОВО** |
| Срок за производство (дни) | `prod_days` | **ГОТОВО** |
| Реална дата на готовност | `ready_date` (advance_paid_at + prod_days, изчислено) | **ГОТОВО** |
| Оставащи дни за производство | `days_left` (изчислено в `supplierOrderView`) | **ГОТОВО** |
| Окончателно плащане — сума | `total_eur − advance_eur` (остатък) | **ГОТОВО** |
| Дата на окончателно плащане | `final_paid_at` | **ГОТОВО** |
| Срок за доставка след плащане | `transport_days` | **ГОТОВО** |
| Очаквана дата на доставка в България | `expected_delivery` (прогнозна преди финалното плащане, реална след) | **ГОТОВО** |
| Статус | `computed_status` (очаквана/поръчана/в производство/в движение/доставена) | **ГОТОВО** |

Спецификацията „Етап 1/Етап 2" (аванс → отброяване → доплащане → транспорт →
очаквана дата) е реализирана точно в `supplierOrderView` — изчислените полета
`ready_date`, `days_left`, `expected_delivery` и `computed_status`.

Достъп: финансите + логистиката (тази сесия — `GET/PUT /api/logistics/supplier-orders`,
нов таб „Поръчки" в Логистика).

| Оставащо от Тъмния_2 | Състояние |
|---|---|
| Прил.1 генериран като Excel + таблицата по поръчки експортирана в Excel | **ЛИПСВА** — Excel експорт съществува за оферти; поръчковият регистър е UI+API, без xlsx export. |

## Обобщение

- **Покрити изцяло**: плащания 50/30/20 и срокове по договора, краен срок от
  реалния аванс, картон на обекта, КС↔спецификации↔рецепти, трите кофи на
  таблото, известия, себестойност от офертата, целият доставнически регистър
  от Тъмния_2 (вкл. прогнозна/реална очаквана дата).
- **Частични**: МПС/механизация от оферти (manual allocations), банкови
  извлечения (ръчно въвеждане), забрана за превишение на КС (tracked issue,
  не твърда), генериране на документи от бланки (DOCX/XLSX).
- **Липсват**: таб „Обекти на клиента" в Клиенти, файлов конвертор,
  Excel експорт на доставническия регистър.
